## 一、异常预警触发规则

系统采用**物理阈值规则引擎**作为第一道防线，独立于 AI 模型运行。每隔 3 秒，实时数据流守护进程（`run_realtime_stream`）为每台设备生成一条传感器数据，写入数据库后**立即**执行阈值检测。

### 1.1 三类物理报警类型

| 报警类型（`alert_type`）| 中文名称 | 触发条件 | 物理含义 |
|---|---|---|---|
| `HIGH_CURRENT` | 主轴过电流物理报警 | `|spindle_current| > 25.0 A` | 切削负载异常偏大，刀具钝化或切削参数不当 |
| `HIGH_POWER` | 主轴过载物理报警 | `spindle_power > 0.20 W` | 主轴输出功率超限，可能过载或轴承异常 |
| `LOW_VELOCITY` | 进给速度异常报警 | `|feed_velocity| > 17.0 mm/s` | 进给速度过高，与正常工况偏差显著 |

> **优先级顺序**：三个条件按 `HIGH_CURRENT → HIGH_POWER → LOW_VELOCITY` 顺序判断，每次触发**至多记录一条**报警（取优先级最高的类型）。

### 1.2 触发判定代码（源自 `run_realtime_stream.py`）

```python
ALERT_THRESHOLDS = {
    'spindle_current': 25.0,   # > 25A → HIGH_CURRENT
    'spindle_power':    0.20,  # > 0.20W → HIGH_POWER
    'feed_velocity':    17.0,  # |v| > 17 mm/s → LOW_VELOCITY
}

def _check_and_create_alert(record):
    sc = abs(record.spindle_current)
    sp = record.spindle_power
    fv = abs(record.feed_velocity)

    if   sc > 25.0: atype = 'HIGH_CURRENT'
    elif sp > 0.20: atype = 'HIGH_POWER'
    elif fv > 17.0: atype = 'LOW_VELOCITY'
    else: return False  # 不触发

    AnomalyAlertLog.objects.create(
        record        = record,
        alert_time    = record.timestamp,
        alert_type    = atype,
        anomaly_score = round(random.uniform(0.60, 0.99), 4),  # ← 见第二节
        is_handled    = False,
    )
    return True
```

### 1.3 传感器数据分布与触发概率

实时数据按**设备编号分组**生成，不同组的传感器均值不同，决定了各组触发报警的概率：

| 设备 ID 段 | 分组 | 主轴电流均值 | 触发主要类型 | AI 置信度范围 |
|---|---|---|---|---|
| 设备 1–5 | Group 1（崭新） | ~15.0 A | 极少触发 | 0–40% |
| 设备 6–12 | Group 2（较新） | ~24.0 A | 边界触发 HIGH_CURRENT | 30–50% |
| 设备 13–19 | Group 3（正常） | ~27.0 A | 频繁触发 HIGH_CURRENT | 41–75% |
| 设备 20–23 | Group 4（老化） | ~31.0 A | 必然触发 HIGH_CURRENT | 60–85% |
| 设备 24–25 | Group 5（故障） | ~40.0 A | 必然触发 HIGH_CURRENT | 76–100% |

> 主轴电流以 `σ=1.5A` 的正态分布随机生成，因此即便均值低于阈值，仍有一定概率触发报警。

### 1.4 Idle / Down 设备的处理逻辑

- **Idle（待机）**：主轴电流 ~0.3A，功率 ~0.002W，进给速度 ~0.0 mm/s — **不会触发报警**
- **Down（停机）**：三个传感器均为 0 — **不会触发物理报警**（停机事件由设备状态变更直接处理）

## 二、AI 置信度（Anomaly Score）

### 2.1 置信度的含义

**AI 置信度（anomaly_score）** 表示逻辑回归模型判断当前传感器读数对应**刀具处于磨损（worn）状态**的概率，取值范围 `[0, 1]`，在前端换算为百分比显示（如 `87.9%`）。

> ⚠️ 注意区分：物理报警的 `anomaly_score` 字段（在 `_check_and_create_alert` 中赋值为 `random.uniform(0.60, 0.99)`）是**随机补充值**，与 AI 模型的 `predict_proba` 输出是**两套独立的值**。前端 Admin 列表中显示的是前者；设备详情弹窗中显示的是后者。

### 2.2 模型架构：逻辑回归（Logistic Regression）

| 属性 | 值 |
|---|---|
| 算法 | `sklearn.linear_model.LogisticRegression` |
| 类别权重 | `class_weight='balanced'`（自动补偿磨损样本少数类） |
| 正则化 | L2，`C=1.0` |
| 求解器 | `lbfgs` |
| 最大迭代 | 1000 次 |
| 训练集划分 | 80/20，分层抽样（`stratify=y`） |

### 2.3 特征工程流水线（训练阶段）

训练时经过 4 个步骤构建 **9 维特征向量**：

```
原始传感器数据（3 维）
  ↓ Step 1: 切削阶段过滤（剔除 Repositioning / Idle 等空转数据）
  ↓ Step 2: 按 device_id 分组，以 5 分钟滚动窗口计算聚合统计
  ↓ Step 3: 生成 9 维特征矩阵
  ↓ Step 4: StandardScaler 标准化（消除量纲差异）
```

**9 维特征说明**：

| # | 特征名 | 计算方式 | 物理意义 |
|---|---|---|---|
| 1 | `spindle_current_mean` | 5 min 滚动均值 | 平均切削负载 |
| 2 | `spindle_power_mean` | 5 min 滚动均值 | 平均功率消耗 |
| 3 | `feed_velocity_mean` | 5 min 滚动均值 | 平均进给速度 |
| 4 | `spindle_current_max` | 5 min 滚动最大值 | 切削力峰值 |
| 5 | `spindle_power_max` | 5 min 滚动最大值 | 功率峰值 |
| 6 | `feed_velocity_max` | 5 min 滚动最大值 | 速度峰值 |
| 7 | `spindle_current_std` | 5 min 滚动标准差 | **刀具震颤强度**（磨损的关键特征） |
| 8 | `spindle_power_std` | 5 min 滚动标准差 | 功率波动幅度 |
| 9 | `feed_velocity_std` | 5 min 滚动标准差 | 速度抖动幅度 |

> 📌 **关键洞察**：`spindle_current_std` 是最重要的特征。刀具磨损时，切削力呈非稳态波动，标准差显著增大；而新刀的切削力非常平稳，标准差接近零。

### 2.4 在线推断（实时 API）

推断时，**简化了特征构造**（以单条记录来近似 5 分钟窗口的聚合值）：

```python
def _predict_proba(record):
    sc = record.spindle_current
    sp = record.spindle_power
    fv = record.feed_velocity

    # 9 维输入：mean 位用实时值，max 位用实时值，std 位填 0（无历史窗口）
    x = np.array([[sc, sp, fv,   # _mean（近似为实时值）
                   sc, sp, fv,   # _max（近似为实时值）
                   0.0, 0.0, 0.0]])  # _std（单点无法计算，填 0）

    x_scaled = _SCALER.transform(x)  # StandardScaler 归一化
    prob = float(_LR_MODEL.predict_proba(x_scaled)[0, 1])  # P(worn=1)
    return round(prob, 4)
```

> ⚠️ **已知局限**：在线推断将 `_std` 全部填 0，意味着模型永远感知不到震颤特征，导致实时置信度偏低（对于磨损设备可能低估风险）。更准确的做法是维护每台设备的滑动窗口缓存。

### 2.5 风险分级阈值

| 置信度范围 | 风险等级 | 前端颜色 | 含义 |
|---|---|---|---|
| > 75% | 🔴 高风险 | `#f56c6c`（红）| 强烈建议换刀或停机检修 |
| 40% – 75% | 🟡 中风险 | `#E6A23C`（橙）| 持续监控，计划预防维护 |
| ≤ 40% | 🟢 低风险 | `#67c23a`（绿）| 刀具状态良好 |

## 三、双轴联动折线图原理

系统中有两处双轴图，设计目标相同：**在同一时间轴上叠加物理信号（电流）与 AI 预测（置信度）**，让操作员无需切换视图即可直观判断物理异常与 AI 预判是否同步发生。

### 3.1 两处图表的对比

| 属性 | Dashboard 全局图 | Device 弹窗图 |
|---|---|---|
| 位置 | 首页"系统异常报警"卡片 | 设备页"AI 诊断详情"弹窗 |
| 数据来源 | `/api/stream/`（随机抽取一台 Running 设备的最新一条） | `/api/stream/<device_id>/`（指定设备近 50 条历史序列） |
| 更新方式 | 定时轮询（每 3 秒 push 一个新点，最多保留 50 点） | 打开弹窗时一次性加载，静态展示 |
| 左轴（蓝） | 主轴反馈电流 `spindle_current`（A） | 主轴反馈电流 `spindle_current`（A） |
| 右轴（红） | AI 故障预警概率（%，`yAxisIndex: 1`，范围 0–100） | AI 预测概率（%，`yAxisIndex: 1`，范围 0–100） |
| 预警标记 | 有：`markLine`（75% 虚线）+ `markArea`（75–100% 红色区域） | 无（纯曲线展示） |

### 3.2 数据流路径图

```
【后端守护进程】
run_realtime_stream.py
  每 3 秒 → 写入 ProductionSensorData 表

        ↓ HTTP GET

【API 层 — views.py】
/api/stream/           → 随机抽 Running 设备最新 1 条
                          + _predict_proba() → anomaly_probability
                          → JSON { spindle_current, anomaly_probability, timestamp }

/api/stream/<id>/      → 指定设备最近 50 条（时序）
                          + 逐条 _predict_proba() → anomaly_score[]
                          → JSON { timestamps[], spindle_current[], anomaly_score[] }

        ↓ setInterval(3000ms)

【前端 JavaScript】
Dashboard:
  tsArr[] / curArr[] / probArr[]   ← 滚动缓冲区（最多 50 点）
  cLine.setOption({
    xAxis: { data: tsArr },
    series: [{ data: curArr }, { data: probArr }]
  })

Device Modal:
  fetch(`/api/stream/${deviceId}/`)
  modalChart.setOption({
    xAxis: { data: labels },        ← HH:MM:SS 时间标签
    series: [
      { data: d.spindle_current },  ← 左轴（yAxisIndex: 0）
      { data: d.anomaly_score  }    ← 右轴（yAxisIndex: 1），0–100%
    ]
  })
```

### 3.3 双轴"联动"的 ECharts 配置原理

两个 Y 轴分别绑定不同量纲的数据，通过 `yAxisIndex` 属性关联：

```javascript
yAxis: [
    {   // 左轴（index: 0）—— 电流，单位 A，自动刻度
        type: 'value', name: '电流(A)', position: 'left',
        axisLabel: { color: '#409EFF' }     // 蓝色标签
    },
    {   // 右轴（index: 1）—— AI 置信度，固定 0–100%
        type: 'value', name: 'AI故障预警(%)', position: 'right',
        min: 0, max: 100, interval: 20,
        axisLabel: { color: '#f56c6c' }     // 红色标签
    }
],
series: [
    { name: '电流',       yAxisIndex: 0, data: curArr  },  // 绑定左轴
    { name: 'AI故障预警', yAxisIndex: 1, data: probArr }   // 绑定右轴
]
```

**tooltip 联动**：ECharts 的 `trigger: 'axis'` + `axisPointer: { type: 'cross' }` 使两条曲线在同一时间点联动显示，鼠标悬停时同时显示电流值和 AI 置信度百分比。

### 3.4 Dashboard 图表的预警标记层

Dashboard 图表在 `AI故障预警` 系列上叠加了两层视觉警示：

```javascript
markLine: {   // 75% 处的红色虚线
    data: [{ yAxis: 75, lineStyle: { color: '#f56c6c', type: 'dashed' } }]
},
markArea: {   // 75%–100% 的红色半透明背景区域
    itemStyle: { color: 'rgba(255, 77, 79, 0.1)' },
    data: [[{ yAxis: 75 }, { yAxis: 100 }]]
}
```

这意味着：当 AI 置信度曲线进入红色背景区（>75%），操作员无需读数字即可直观感知风险临界。

### 3.5 Device 弹窗图的辅助快照面板

设备弹窗右侧同步显示最新时间点的**关键特征快照**：

| 显示项 | 数据来源 | 颜色逻辑 |
|---|---|---|
| 主轴反馈电流 | `spindle_current`（A） | 固定 |
| 主轴输出功率 | `spindle_power`（W） | 固定 |
| AI 磨损置信度 | `anomaly_score[-1]`（序列最后一点） | `> 70%` → 红色；`≤ 70%` → 绿色 |

## 五、待优化项

| 问题 | 当前状态 | 建议方案 |
|---|---|---|
| 在线推断 `_std` 为 0 | 会低估磨损风险 | 在内存中维护每台设备最近 N 条记录的滑动窗口缓存 |
| 物理报警的 `anomaly_score` 为随机值 | 与 AI 输出不一致 | 改为写入 `_predict_proba()` 的实际推断结果 |
| 单点 `mean/max` 用同一实时值 | 特征信息冗余 | 同上，维护滑动窗口后可计算真实均值和最大值 |
| Device 弹窗图无预警标记线 | 无法直观判断 75% 阈值 | 添加与 Dashboard 相同的 `markLine` + `markArea` |
