# 工业生产数据异常预警系统 —— 系统实现 FAQ 与技术答疑 (V3.5.0)

本文档旨在回答系统实现过程中的核心工程细节与设计初衷。

---

## 1. 后端文件职责与范式
**Q: Django 采用 MTV 范式，那 `models.py` 和 `views.py` 之外的代码是干什么的？**
*   **A**: 虽然 Django 核心是 MTV，但在复杂项目中我们引入了 **Service 层**（如 `services/ai_service.py`）。
    *   **`views.py`** 仅负责处理 HTTP 协议逻辑。
    *   **`services/`** 负责处理纯业务/算法逻辑。这样做的目的是为了解耦，使得 AI 算法可以被 Web 视图调用，也可以被后台 Agent 脚本调用，避免代码重复。

**Q: `IndustrialWarningSystem` 目录是做什么的？**
*   **A**: 这是 Django 的 **项目配置中心**。
    *   `settings.py`: 相当于整个系统的“说明书”，定义了数据库在哪、Redis 在哪、使用了哪些组件。
    *   `urls.py`: 系统的“总机”，决定了用户输入的每一个网址该转接到哪个后台处理函数。

---

## 2. 前端架构与交互
**Q: 前端是如何实现的？路由请求封装是怎么样的？**
*   **A**: 我们采用了 **HTMX + Alpine.js** 的现代前端方案。
    *   **核心**: 放弃了笨重的单页框架（React/Vue），使用 **超媒体驱动**。
    *   **封装**: 你的直觉是对的，HTMX 请求封装的是 **HTML 片段** 而不是 JSON。当你在侧边栏点击“设备列表”时，后端直接返回渲染好的 HTML 列表，前端直接将其“塞进”主内容区。这种方式不仅快，而且由于不涉及 JSON 解析和前端模板渲染，系统的内存占用极低。

---

## 3. 算法与推断流程
**Q: 推断算法的流程是怎么样的？是等模拟数据出来立马推断吗？**
*   **A**: **是的，即时推断。**
    1.  **数据产出**: `simulate_real_cnc_data.py` (后台引擎) 每 3 秒产生一次传感器数据。
    2.  **原地推断**: 引擎在将数据存入数据库 **之前**，会立即调用 `ai_service.predict_proba()`。
    3.  **持久化**: 最终存入 MySQL 的每一条记录都已经自带了 `anomaly_score`。
    4.  **消费**: Web 前端和 Agent 只需要从数据库或 Redis 中“捡现成”的分数即可。这种“生产端推断”模式保证了系统的高实时性。

---

## 4. 核心创新点实现
**Q: Agent 和 AI 服务的核心代码在哪里？**
*   **A**: 
    *   **`ai_service.py`**: 实现了“切削触发更新”策略，通过数学方法（EMA）过滤掉工业现场的背景噪音。
    *   **`agent_service.py`**: 实现了 RAG（基于本地 Markdown 文档的知识检索）和 Tool-use（自动读取实时数据并生成诊断建议）。

> [!NOTE]
> 本项目的核心价值在于将 **机器学习的概率** 转化为了 **工业现场的可操作逻辑**，通过 Agent 实现了从预警到排障的全自动化。
