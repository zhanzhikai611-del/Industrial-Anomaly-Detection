### V2.2.0 产品需求文档 (PRD)

**状态**：草案 (Draft) / 架构升级专项
**版本**：V2.2.0
**更新日期**：2026-03-10

---

#### 1. 背景与目标 (Background & Objectives)

随着系统进入 V2.2.0 阶段，原有的“单中心”后台管理式界面已无法满足工业场景下“实时生产干预”的需求。目前的系统虽有强大的 AI 预警算法与 OEE 统计逻辑，但缺乏一个直观的“物理映像”入口。

**核心目标**：实现“数据监测 (Vision)”与“仿真控制 (Factory)”的职能分离，通过可视化手段将“数据模拟引擎”升级为直观的 **2D 数字孪生工厂界面**，同时确保现有系统的所有功能资产（仪表盘、账号管理等）完整保留。

---

#### 2. 交互架构重构 (Architecture Remodel)

##### 2.1 双中心平行逻辑 (Dual-Center)
系统由单一层级升级为“双中心”并行的顶部导航逻辑：

*   **CNC Vision (数据洞察中心)**：
    *   **定位**：全局健康度与事后分析。
    *   **结构**：沿用原侧边栏导航，包含：**仪表盘、设备监控、事件中心、账号管理、系统设置**。
    *   **改动**：在顶部 Header 增加快速切换至 Factory 的入口。
*   **Digital Factory (数字孪生工厂)**：
    *   **定位**：实时仿真映像与即时干预。
    *   **功能**：2D 孪生矩阵、实时风险评分、仿真中枢控制台。

##### 2.2 导航体系 (Navigation System)
*   **Top-Bar (中心切换)**：控制全站处于 Vision 或 Factory 视角。
*   **Sidebar (功能导航)**：在 Vision 视角下完整保留；在 Factory 视角下可根据需要精简，为数字孪生大屏腾出显示空间。

---

#### 3. Digital Factory 功能定义 (Digital Factory Specifications)

##### 3.1 2D 孪生矩阵卡片 (2D Twin Matrix)
*   **布局**：5×5 矩阵排列，映射车间 25 台设备的物理位置。
*   **物理状态映射 (Physical Status Mapping)**：将后端模拟引擎的实时变量直接映射至前端动效：
    *   **Running (绿色/蓝色波纹动效)**：对齐 `DeviceInfo.current_status == 'Running'`，终端每 3s 成功写入数据时触发。
    *   **Idle (灰色静态)**：对齐 `DeviceInfo.current_status == 'Idle'`。
    *   **Stopped (红色停止动效)**：对齐 `DeviceInfo.current_status == 'Down'`。当单机处于停机（Down）状态时，前端卡片冻结并显示红色警示。
    *   **System Paused (UI 遮罩)**：当全局模拟开关 `is_realtime_active` 为 False 时，矩阵呈现半透明锁定状态。
*   **实时物理指标 (Real-time Metrics)**：
    *   **瞬时性能 (P值)**：基于 **V2.1.2 滚动窗口法**计算的瞬时表现度（注：启动初期 5 分钟内数值会有爬升感）。
    *   **AI 风险评分**：实时风险特征组评估得分。
    *   **本次累计产量 (Session Yield)**：展示自点击“启动”开关以来的良品产出。需配合后端 `session_uuid` 实现数据隔离。
    *   **当前原始值**：实时展示 `spindle_current`（电流）、`spindle_power`（功率）、`feed_velocity`（进给速度）。

##### 3.2 仿真中枢控制台与重置逻辑 (Console & Reset Logic)
*   **集成开关**：直接在前端控制数据流的启动 (Start) 与 暂停 (Pause)，对接后端 `SystemConfig`。
*   **V2.2.0 风险重置入口 (Risk Reset)**：这是 Factory 界面唯一保留的“分析干预”功能，用于清空 AI 记忆。
    *   **操作逻辑**：当用户在本地终端或设置中调整了模拟波动范围后，点击“重置风险特征组”。
    *   **后台联动 (Backend Action)**：
        *   **Cache Purge**：后端调用 `cache.delete_pattern("feature_seq_*")` 清空 Redis 中的滚动窗口序列。
        *   **Vision Notify**：通过 WebSocket 向 CNC Vision 发送广播，强制前端清空旧的红色报警闪烁提示。

##### 3.3 Engine Log 智能视窗交互 (Engine Log Intelligence)
仿真引擎的原始输出通过以下链路透传至前端：
1.  **Backend Trace**：`run_realtime_stream.py` 在写入 DB 的同时，将执行结果推入 Redis List (`simulation_logs`)。
2.  **WS Broadcast**：`FactoryConsumer` 实时监听 Redis 变更，通过 WebSocket 广播至 UI 层。

**显示模式切换**：
*   **全局模式 (Global Mode - 未选中设备)**：
    *   显示全厂 25 台设备的推送汇总汇报。
    *   日志示例：`[12:00:03] ENGINE: 25 nodes written successfully. (Session: UUID-4512)`
*   **设备模式 (Device Mode - 选中单台设备)**：
    *   **历史轨迹**：展示该设备本次模拟周期的物理参数列表（如电流、转速的历史均值）。
    *   **跨中心指令 (Maintenance Advice)**：从 CNC Vision 异步抓取该设备的“维修建议”并置顶显示（例如：`[AI 建议] 主轴负荷异常，建议检查刀具磨损`）。

#### 4. 技术实现要点 (Technical Requirements)

*   **非破坏性改动**：所有的 Vision 页面路由与逻辑保持不变。
*   **WebSocket 扩展**：新增 `FactoryConsumer`，专门负责频率为 3s/次的孪生快照数据推送。
*   **仿真引擎闭环**：通过前端 API 修改数据库配置，让 `simulate_real_cnc_data.py` 脚本能根据前端意图动态响应。
*   **页面独立性 (Page Independence)**：虽然共用 Django 核心逻辑，但 `Digital Factory` 页面采用完全独立的前端路由与布局模板，不携带 Vision 系统的侧边栏，采用全屏“数字驾驶舱”设计。
*   **数据推送 Payload 升级 (Push Logic)**：
    为了支撑上述 UI，数据推送包应包含以下结构：
    ```json
    {
        "type": "factory_update",
        "device_id": "CNC-001",
        "data": {
            "status": "Running",
            "raw_metrics": {"spindle_current": 25.4, "spindle_power": 0.12, "feed_velocity": 19.5},
            "session_yield": 128,
            "session_uuid": "SIM-2026-03-10-A",
            "vision_advice": "建议检查主轴润滑"
        }
    }
    ```

*   **预期行为说明 (Behavioural Note)**：
    *   **5-min Ramp-up**：由于单机 OEE 采用 5 分钟滑动窗口保护逻辑，设备重置或启动后的前 5 分钟，UI 显示的 P 值将处于稳定爬升期。此为系统平滑设计的预期表现，无需作为 Bug 处理。

---

#### 5. 验收标准 (Acceptance Criteria)

1.  用户可从顶部 Tab 瞬间从“仪表盘”切换到“数字孪生工厂”，且不丢失登录状态。
2.  点击 Factory 侧的 Reset 按钮后，对应的矩阵卡片能在 1 个步长（3s）内由红色风险状态变回正常状态，且对应的 Vision 侧 OEE 数值能观察到回升。
3.  关闭 Factory 侧的控制开关，Vision 侧的所有图表停止更新；开启后恢复。

---
#### 6. 页面功能架构建议 (Functional Architecture & Layout)

Digital Factory 页面采用“左-中-右”三段式沉浸布局：

##### 6.1 左侧：2D 孪生矩阵 (Twin Matrix Grid)
*   **5×5 分布式卡片**：映射全车间 25 台设备。
*   **状态反馈**：卡片根据 WebSocket 推送的数据流实时变换动效（如切削时的波纹扩散效果）。
*   **点击交互**：点击任意卡片将该设备标记为 `Active Device`，并触发右侧视窗的自动切换。

##### 6.2 中间：全局状态监控窗 (Global Pulse Window)
*   **资产汇总**：实时显示 Running, Idle, Down, Total 的设备数量对比。
*   **稼动率心跳**：以垂直进度条或微型刻度盘展示全厂瞬时平均稼动率。
*   **在线节点清单**：滚动展示当前有数据上报的 IP/节点编号。

##### 6.3 右侧：智能日志/数据视窗 (Smart Data Panel)
*   **全厂引擎仿真日志 (Engine Log - 默认模式)**：
    *   实时同步终端控制台的运行状态（由 `simulate_real_cnc_data.py` 推送的消息）。
    *   展示内容：`[TIMESTAMP] SYSTEM: Broadcast data to 25 nodes.`
*   **设备历史轨迹 (Device History - 选中设备后触发)**：
    *   **自动切换**：当左侧卡片被选中时，面板平滑切换为该设备的详细数据流。
    *   **轨迹明细**：以表格或时序列表形式展示该设备最近 50 条传感器原始数据（电流、转速、负载）。
    *   **快速返回**：面板底部提供“返回全局日志”按钮。

#### 7. V2.2.0 实现技术说明 (Implementation Reference)

> 此章记录 V2.2.0 开发完成后的**实际实现细节**，供后期维护参考。

##### 7.1 后端文件清单

| 文件 | 作用 |
|---|---|
| `monitor/consumers.py` | 新增 `FactoryConsumer` 类，独立于 `CopilotConsumer` |
| `monitor/routing.py` | 注册新路由 `ws/factory/` |
| `monitor/views.py` | 新增 `factory_view(request)` 函数 (`@login_required`) |
| `monitor/urls.py` | 新增 `path('factory/', views.factory_view, name='factory')` |
| `monitor/templates/monitor/factory.html` | 全屏独立模板，不继承 `base.html` |
| `monitor/templates/monitor/base.html` | 顶部 Header 新增双中心 Tab 导航 |

##### 7.2 FactoryConsumer 实现细节

**WebSocket 路由**：`ws/factory/`

**推送频率**：每 **3秒** 推送一次全量快照

**实际 Payload 结构**：
```json
{
  "type": "factory_snapshot",
  "timestamp": "HH:MM:SS",
  "is_stream_active": true,
  "devices": [
    {
      "device_id": 1,
      "device_name": "C-高光-01",
      "device_type": "高光机组",
      "current_status": "Running",
      "spindle_current": 25.4,
      "spindle_power": 0.12,
      "feed_velocity": 19.5,
      "anomaly_score": 0.28,
      "oee": 0.91,
      "session_yield": 128,
      "machining_process": "Layer 1 Up"
    }
  ]
}
```

> 注：实际实现简化了 PRD 所始设计的层级封装结构，改为全部设备**平展入数组** (`"devices": [...]`) 一次性推送，陈列文套改为 `factory_snapshot`。

**支持的控制指令** (client → server)：

| 指令 `action` | 功能 |
|---|---|
| `start_stream` | 将 `SystemConfig.is_realtime_active` 设为 `True` |
| `stop_stream` | 将 `SystemConfig.is_realtime_active` 设为 `False`，前端显示暂停遮罩 |
| `reset_groups` | 执行风险特征重置：清空 Redis Cache `feature_seq_*` |

##### 7.3 前端实现细节

**模板结构** (`factory.html`)：独立 HTML，不继承 `base.html`，自含 CSS + JS。

**布局大区 (fixed 定位层)**：
```
.navbar     (h=56px, top=0)         ← 导航栏
.factory-main                        ← top=56px, bottom=52px
  .left-area
    .matrix-wrap  (flex:1)           ← 5×5 矩阵
    .node-panel   (w=180px)          ← NodeStatus 面板
  .log-panel      (w=260px)          ← Engine Log 面板
.ctrl-bar   (h=52px, bottom=0)      ← 控制栏
```

**设备卡片状态映射**：

| `current_status` | CSS 类 | 视觉效果 |
|---|---|---|
| `Running` | `.status-Running` | 顶部蓝色 2px 边框 + 旋转光环 |
| `Idle` | `.status-Idle` | 顶部灰色 2px 边框 |
| `Down` | `.status-Down` | 顶部红色 2px 边框 + 闪烁较色覆盖层 |

**OEE 展示逻辑**：取自 `FactoryConsumer` 每次推送的 `oee` 字段，直接显示，不在前端重算。

##### 7.4 导航高亮逻辑 (V2.2.0 双中心 Tab)

- **实现位置**：`base.html` Header + `factory.html` Navbar
- **CSS 类**：`.nav-center-tab` / `.nav-center-tab.active`
- **高亮规则**：
  - `CNC Vision` ：当 `request.resolver_match.url_name != 'factory'` 时高亮（即所有侧边栏页面均保持蓝色点亮）
  - `Digital Factory`：当 `url_name == 'factory'` 时高亮
