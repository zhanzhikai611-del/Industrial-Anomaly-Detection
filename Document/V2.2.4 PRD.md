### V2.2.4 产品预研文档 — 前端分离进化路径选型 (已决议)

**状态**：已决议 (Resolved)
**版本**：V2.2.4 -> 迈向 V3.0
**更新日期**：2026-03-14

---

#### 1. 背景 (Background)
在 V2.2.3 完成“物理资产剥离”后，项目已具备良好的模块化基础。目前的痛点在于：如何实现在不重写 80% 代码的前提下，获得 **单页应用 (SPA)** 的丝滑体验（如跨页面状态保留、局部极速刷新）。

#### 2. 前端架构演进方案对比 (Technology Comparison)

针对本项目（基于机器学习的工业预警系统），以下是四种轻量级演进方案与 Vue 框架的深度对比：

| 维度 | **HTMX** (局部刷新流) | **Alpine.js** (轻量响应式) | **Turbo/Pjax** (框架封装) | **Vue 3** (工业级框架) | **Vanilla JS** (现状进化) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **核心思想** | 增强 HTML，让 HTML 具备 AJAX 能力 | 在 HTML 中直接写数据驱动逻辑 | 拦截链接跳转，局部替换 Body 内容 | 完全的数据驱动 + 虚拟 DOM | 原生 JS 引擎手写状态同步 |
| **迁移成本** | **极低**。后端只需改写视图返回局部模板 | **低**。只需在 HTML 中添加属性指令 | **极低**。几乎不需要改动代码逻辑 | **高**。需重写组件，配置构建工具 | **中**。需手写大量状态维护代码 |
| **SPA 体验** | **好**。可以实现无感局部刷新 | 一般。主要解决交互，不解决跳转 | **极佳**。全站跳转无刷新感 | **最高**。完整的单页应用体验 | 一般。取决于手写封装的完善程度 |
| **状态保留** | 通过局部刷新，侧边栏 AI Agent 可常驻 | 较难。跳转页面后内存状态会丢失 | **原生支持**。整个基座 (Base) 跨页不关闭 | **完美支持**。状态由全局 Store 管理 | 难。需手写复杂的 `sessionStorage` 映射 |
| **技术栈需求** | Django Template 依然是主力 | 纯前端逻辑，学习曲线极平缓 | 基本无感，侧重于服务端渲染 (SSR) | 需掌握组件化、Vite、Node 环境 | 需掌握高质量的原生 JS 函数封装 |
| **适用场景** | 追求开发速度，利用现有 Django 逻辑 | 复杂且频繁的小型组件交互（如弹窗） | 想要极致的“伪 SPA”加载体验 | 长期维护、多人协作的大型监控应用 | 极其关注性能，追求 0 依赖加载速度 |
| **构建工具** | 无需 Node.js | 无需 Node.js | 无需 Node.js | **必须 Node.js/Build Step** | 无需 Node.js |

#### 3. 核心方案深度解析 (Deep Dive)

##### 3.1 HTMX (The "Hypermedia" Way) — *推荐：高性价比进化*
*   **适用性**：最契合工业看板场景。当用户点击“设备详情”时，HTMX 只从后端取回一个小表格 HTML 给替换掉，速度比完整刷页面快 10 倍。
*   **对 V3.0 的意义**：它不仅是技术，更是一种能让后端逻辑保持简单，前端交互变得高级的艺术。

##### 3.2 Turbo / Hotwire — *推荐：最省力切换*
*   **适用性**：如果你不介意侧边栏 AI Agent 在跳转时重新初始化（虽然它看起来没刷页面），它是最省力的。它能让你的系统瞬间告别“白屏闪烁”。

##### 3.3 Alpine.js — *适配：局部交互增强*
*   **适用性**：现在的 `account.js` 里有大量的 `document.getElementById('...').style.display = 'block'`。如果换成 Alpine，代码会干净得像 Vue，但不需要配置复杂的编译环境。

##### 3.4 Vue 3 / React — *慎重：长线重构*
*   **适用性**：除非你确定未来 1 年要在前端增加诸如“拖拽式生产线排产”、“复杂的工作流编辑器”等功能，否则它的维护成本对目前的单人/小型开发序列来说过重。

#### 4. 决议结论 (Strategic Decision)

针对 V3.0 **“逻辑虚拟化”** 的路径，现已正式确立为 **“现代原教旨主义 (Modern Fundamentalism)”**：

1.  **架构基调**：**Django + HTMX + Alpine.js**。回归 HTML 本质，以极低的成本获取接近单页应用 (SPA) 的体验。
2.  **基座层面 (HTMX)**：全面引入 **HTMX**。用局部 HTML 替换解决“跨页面跳转刷新”的体验顽疾，实现低成本的 SPA 级路由体验，让 AI Agent 等全局组件在页面切换时无感常驻。
3.  **组件层面 (Alpine.js)**：在需要状态绑定的 UI 组件（如 Modal 弹窗、Dropdown 下拉、Toggle 切换）中全面引入 **Alpine.js**，以声明式语法替代繁琐的原生 DOM 命令式操作。
4.  **核心控制 (Vanilla JS)**：保留现有物理剥离后的 **App Engine (Vanilla JS 命名空间)**。针对复杂的业务逻辑（如 WebSocket 数据流、Three.js 孪生渲染、ECharts 图表），原生 JS 引擎依然是最稳健、性能最高的支撑。

---
> **决议落地**：本预研方向已确认。V3.0 的后续施工将首先启动环境注入工作（在 `base.html` 中引入 HTMX 与 Alpine.js 的 CDN 资源），并逐步对各页面的渲染与交互模式进行改造。
