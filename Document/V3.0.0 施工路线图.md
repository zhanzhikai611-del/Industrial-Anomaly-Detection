# V3.0 “现代原教旨主义”施工路线图 (Django + HTMX + Alpine.js)

本计划旨在将现有的 Django 多页应用 (MPA) 逐步改造为具备单页应用 (SPA) 体验的现代化架构。核心目标是实现 **局部刷新（HTMX）**、**声明式交互（Alpine.js）** 以及 **核心引擎保留（Vanilla JS）**。

## 施工核心原则
- **小步快跑**：每一步必须可独立部署、可验证。
- **视觉一致**：重构前后 UI 渲染结果必须 1:1 还原。
- **状态常驻**：确保侧边栏 AI Agent 在“页面切换”时 WebSocket 连接不中断。

---

## 第一阶段：基础设施注入与环境搭建 (Environment Injection)
**目标**：在不改动业务逻辑的前提下，建立 V3.0 的技术运行环境。

- [x] **1.1 资源引入**：在 `base.html` 中引入 HTMX 和 Alpine.js 的 CDN（或静态文件）。
- [x] **1.2 建立 HTMX 骨架**：
    - 在 `base.html` 的 `<main>` 容器上添加 `id="main-content"`。
    - 在 `<body>` 或根节点配置 `hx-headers='{"X-CSRFToken": "{{ csrf_token }}"}'`。
- [x] **1.3 Django 局部渲染支持**：
    - 编写一个简单的 `PartialTemplateMixin` 或 `middleware`，能够根据 `HX-Request` 头部判断返回完整页面还是仅返回 `content` 块。

**✅ 验证点**：控制台无报错，通过浏览器插件查看 HTMX/Alpine 已成功加载。

## 第二阶段：局部交互升级 (Alpine.js Refactoring)
**目标**：用声明式语法替代 `account.js`, `setting.js` 中繁琐的 DOM 操作。

- [x] **2.1 弹窗与下拉重构**：
    - 选取 `account.html` 与 `setting.html` 作为首个试点。
    - 将模态框、分段选择器（Segmented Control）等交互从原生 JS 迁移至 Alpine.js。
- [ ] **2.2 表单验证与状态绑定**：
    - 使用 `x-model` 绑定输入框，简化前端校验逻辑。
- [x] **2.3 全局 Toast 通知**：
    - 在 `base.html` 建立或在各页面独立实现基于 Alpine 的消息组件。

**✅ 验证点**：账号管理与系统设置页面的所有弹窗、通知交互均实现“数据驱动”，代码可维护性大幅提升。

## 第三阶段：路由虚拟化与 SPA 体验 (HTMX Core)
**目标**：消除切换页面时的“白屏闪烁”，实现 AI Agent 跨页常驻。

- [x] **3.1 侧边栏链接转换**：
    - 将 `sidebar.html` 中的 `<a>` 标签改造为 `hx-get`。
    - 设置 `hx-target="#main-content"` 和 `hx-push-url="true"`。
- [x] **3.2 处理局部加载的 JS 初始化**：
    - 解决局部刷新后 `extra_js` 块不重新执行的问题。
    - 利用 HTMX 的 `htmx:afterSettle` 事件重新触发对应页面的 `AppEngine.init()`。
- [x] **3.3 AI Agent 常驻验证**：
    - 验证从 Dashboard 切换到 Device 时，侧边栏的对话历史和 WebSocket 是否保持。

**✅ 验证点**：点击导航栏图标，中间内容区域瞬间切换，且地址栏 URL 随之改变，整个过程中侧边栏无刷新。

- [x] **4.2 异步数据流：混合驱动落地**：

    - **JS 保留**：成功保留 ECharts 图表引擎的独立控制，解决局部刷新后的渲染冲突。 @done(2026-03-17)

**✅ 验证点**：从工厂页跳转回仪表盘后，浏览器显存占用能迅速回落，无孤儿连接残留。
