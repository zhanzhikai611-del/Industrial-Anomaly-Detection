# 工业生产数据异常预警系统 —— 后端架构与核心逻辑 (V3.5.0)

## 1. 深度架构设计：Service-Oriented MTV
本项目在 Django 标准的 **MTV (Model-Template-View)** 架构基础上，引入了 **Service Layer (服务层)** 和 **Task Layer (任务层)**，实现了业务逻辑、推断算法与请求处理的深度解耦。

### 1.1 核心层级职责
*   **View 层 (`monitor/views.py`)**: 仅负责请求调度。通过 `HX-Target` 头识别 HTMX 请求，返回 HTML 碎片或全量页面；同时处理 RBAC 鉴权。
*   **Service 层 (`monitor/services/`)**: 系统核心逻辑所在地。
    *   `stats_service.py`: 负责全量 OEE 指标计算、滑动窗口聚合及看板统计。
    *   `ai_service.py`: 管理内存中的逻辑回归模型，执行实时推断与 EMA (指数移动平均) 平滑。
    *   `cache_service.py`: 封装 Redis 读写逻辑，包括设备快照、产量计数器和看板缓存。
*   **Task 层 (`core_scripts/`)**: 独立于 Web 进程运行的守护脚本。
    *   `simulate_real_cnc_data.py`: 数据仿真引擎，通过多线程模拟工业现场数据流。

## 2. 核心业务逻辑实现

### 2.1 OEE 指标体系与滑动窗口 (`stats_service.py`)
系统摒弃了静态累计，采用 **30 分钟滑动窗口聚合 (1:1 物理对齐法)**。
*   **可用性 (Availability)**: `(加载时间 - 停机时间) / 加载时间`。
*   **性能稼动率 (Performance)**: 使用 `actual_run_min` (扣除停机后的纯运转时间) 计算理论最大产能，确保设备恢复瞬间 P 值能立即反弹。实现函数：`calculate_rolling_oee`。
*   **质量合格率 (Quality)**: `良品产出 / 投入总数`。通过 `db_actual` 与 `db_input` 的数据库聚合值确保口径一致。

### 2.2 实时 AI 推断与 EMA 平滑 (`ai_service.py`)
为了解决工业噪声导致的风险值剧烈跳变，系统实现了 **内存 resident 推断**：
*   **特征工程**: 函数 `predict_proba` 将 3 维原始数据扩充为 13 维统计特征（均值、交互特征等）。
*   **EMA 平滑**: 对模型原始输出进行 `EMA(t) = α * Prob(t) + (1-α) * EMA(t-1)` 处理，使曲线更符合物理常识。
*   **缓冲区重置**: 当设备执行 `api_device_reset` 时，联动调用 `reset_device_buffer` 清空历史状态，实现风险分数瞬间归零。

### 2.3 RBAC 权限控制逻辑
系统通过自定义装饰器 `role_required` 实现了三级权限管理：
*   **Admin**: 访问 `/account/`、`/setting/`，执行 `api_create_account` 等系统级操作。
*   **Engineer**: 可执行设备重置、维修工单下发。
*   **Operator**: 仅限查看看板与处理报警。

## 3. 进程间通信与数据同步 (IPC)
由于 Web 进程 (Django) 与 仿真进程 (Simulation) 内存不互通，系统采用 **Redis Hash** 作为“唯一事实来源”：
1.  **写入端**: 仿真引擎生成数据后，同步调用 `CacheService.update_device_snapshot` 写入 Redis。
2.  **读取端**: `stats_service.get_device_matrix_data` 优先扫描 Redis。如果命中，响应时间可从 100ms 级别优化至 2ms。
3.  **兜底逻辑**: 若 Redis 失效，系统通过 `ProductionSensorData.objects.latest()` 从 MySQL 数据库回填快照。

## 5. 高级特性实现 (V3.5.0 专项)

### 5.1 检索增强生成 (RAG) 链路
系统通过 `agent_service.py` 实现了专家级故障诊断：
*   **语义层**：利用 `Sentence-Transformers` 将本地 `/Document/` 下的 PDF/MD 手册向量化，存储于 FAISS。
*   **推理层**：后端在识别到 `AI_SOFT_SIGNAL` 告警时，自动触发 Context 检索，构造包含实时参数、历史趋势和技术文档片段的增强 Prompt。

### 5.2 基于 ASGI 的实时双工通信
为了实现“亚秒级”预警响应，系统底层从 WSGI 切换为 **ASGI (Daphne)**：
*   **实时推送**：利用 Django Channels 建立长连接。当 Redis Snapshot 更新时，触发 `GroupMessage` 推送，避免了高频 AJAX 请求带来的服务器压力。

### 5.3 系统稳定性监控 (Self-Healing)
*   **状态监测**：`SystemLog` 实时记录守护进程的心跳。
*   **自动复位**：针对 Redis 数据污染（如 OEE 数值锁死），后端提供了硬件级重置逻辑，可一键清理内存残留并重新初始化设备 buffer。
