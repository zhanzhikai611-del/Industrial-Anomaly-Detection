### V2.1.0 PRD：双模态 AI 交互中心与 Ask 模式增强

#### 1. 版本核心目标

在 V2.0.0 实现 Copilot 自动接管与闭环治理的基础上，V2.1.0 旨在引入“人机协同”的 **Ask 模式 (智能问答)**。通过统一的入口重构与大语言模型（LLM）的 **Function Calling** 能力，系统将能在“主动防御（Copilot）”与“被动咨询（Ask）”之间无缝切换，彻底解决复杂工业系统的信息检索与认知负荷痛点。

##### 2.1 AI 入口设计：热区切割按钮 (Split Button)

舍弃单一开关，采用具有状态记忆功能的热区切割按钮。

- **左侧热区 (Main Action)**：占比 70%~80%。显示当前激活模式的 Icon（🤖 自动接管 或 💬 智能问答）及文字。点击即刻启动当前模式。
- **右侧热区 (Dropdown Drop)**：占比 20%~30%，带有一条极细的 1px 竖线分割和一个下拉箭头 `⌄`。点击后弹出模式选择菜单：
  - `Copilot 模式 (全屏接管)`
  - `Ask 模式 (悬浮咨询)`
- **交互记忆**：当用户在下拉菜单中选择某个模式后，左侧主热区的 Icon 和功能将自动更新为用户的最后一次选择。

##### 2.2 Ask 模式视觉规范：轻量化 SaaS 悬浮窗

为避免遮挡底层 5x5 拓扑蜂窝矩阵，Ask 模式的对话框需严格遵循 V1.4.0 的轻量化工业质感。

- **Glassmorphism (毛玻璃) 容器**：悬浮在屏幕右侧（Width: 340px），背景色设定为 `rgba(26, 26, 26, 0.6)` 并搭配 `backdrop-filter: blur(20px)`。
- **极细工业描边**：1px 的 `rgba(255, 255, 255, 0.1)` 边框，顶部辅以微弱的蓝色（#4A90E2）线性渐变发光。
- **对话流极简渲染**：
  - **用户气泡**：取消实心背景，采用左侧 `2px` 蓝色竖线缩进显示。
  - **AI 气泡**：透明背景，对于模型返回的 SQL 数据或状态列表，强制使用**单色等宽字体 (Monospace)**。

##### 2.3 视觉与物理状态隔离 (核心阻断逻辑)

Copilot 模式和 Ask 模式在前端 DOM 树中的物理状态必须严格互斥。

- **切入 Copilot 模式**：
  - 挂载 `#copilot-overlay` 全屏蒙层，设置 `pointer-events: auto` 阻断用户对底层图表的点击。
  - 为 `body` 添加 `.copilot-active` 类，触发屏幕边缘的浅蓝色“呼吸灯”动效。
- **切入 Ask 模式**：
  - **强制移除** `.copilot-active` 和蒙层阻断，恢复用户的鼠标点击权限，同时隐藏呼吸灯。
  - 弹出 Ask 毛玻璃对话框，光标自动 Focus 到输入框。

#### 3. 核心业务逻辑：Function Calling (工具调用) 架构

##### 3.1 逻辑链路：大模型与后端的“三次握手”

当用户在 Ask 模式输入：“CNC-01 今天怎么一直在报错，跟 Punch-02 比它的良率 Q 怎么样？”时，系统将执行以下链路：

1. **意图路由 (Router)**：前端通过 WebSocket 将 `{mode: "ask", text: "..."}` 发往后端的 `CopilotConsumer`。
2. **第一轮 LLM 请求 (Tool Injection)**：后端不直接查库，而是将用户文本与系统预设的 `tools`（JSON 格式的工具说明书，包含 `get_device_recent_data` 函数）发给 LLM。
3. **参数提取与本地调用**：LLM 识别到需要查库，停止闲聊，返回结构化指令：`{"name": "get_device_recent_data", "arguments": "['CNC-01', 'Punch-02']"}`。后端截获该指令，执行 Django ORM 查询，精准获取这两台设备的 $OEE$ 状态与最近 10 条 `anomaly_alert_log` 记录。
4. **第二轮 LLM 请求 (Context Fusion)**：后端将查到的真实数据库 JSON 结果，以 `tool` 角色发回给 LLM。
5. **最终输出 (Generation)**：LLM 结合真实的工业上下文，生成自然语言分析，推送到前端对话框。

#### 3.2 优势与系统安全保障

- **不需要本地部署**：无需本地部署就能实现Text-to-SQL的效果。
- **Token 极致优化**：无需将全厂 25 台机床的数据全量塞入 Prompt，按需精准查询。
- **只读隔离 (Read-Only Isolation)**：Ask 模式下的 `get_device_recent_data` 仅执行 `SELECT` 操作，严禁在此模式下修改 `current_group_id` 或 `current_status`，确保数据资产的绝对安全。

### 4.  接口与技术规范

#### 4.1  WebSocket 消息体更新 (前后端协议)

为了复用目前的 ASGI `CopilotConsumer`，需在 JSON payload 中增加 `mode` 标识：

JSON

```
// Frontend -> Backend
{
  "action": "chat",
  "mode": "ask", // 区分 "copilot" 和 "ask"
  "message": "帮我看看精雕机09的最新状态"
}

// Backend -> Frontend
{
  "type": "ask_reply",
  "content": "CNC-精雕-09 目前处于 Down 状态，最近发生 3 次主轴过载报警...",
  "is_loading": false
}
```

####4.2 本地工具函数设计 (`tools.py`)

在 Django 后端需新增供 LLM 调用的核心查询函数：

- `get_device_recent_data(device_names: list)`：接收设备名数组，联表查询 `DeviceInfo` 和 `AnomalyAlertLog`，返回结构化的 JSON 数据供 LLM 消化。

### 5. 准开发实施方案 (已定架构)

根据最新的可行性分析结论，目前已经解决架构中的核心矛盾，V2.1.0 版本的正式开发行动准则如下：

#### 5.1 前端：原生 JS + CSS 极简组件化 (坚决不引入 Vue)
- **技术选型**：为了避免项目变得臃肿与风格撕裂，完全舍弃引入 Vue.js，使用纯原生 JS (Vanilla JS) + CSS 变量实现。
- **组件落地**：编写原生的 Split Button 组件。左侧主热区绑定对应的 `startCopilot()` 或 `openAskModal()` 方法，右侧热区通过绑定点击事件控制 CSS display 的下拉菜单显隐即可。
- **状态逻辑**：编写状态切换时蒙层以及 `.copilot-active` 类的挂载/卸载逻辑，实现视觉上的严格隔离。

#### 5.2 后端：WebSocket 状态机与协程管控
- **痛点解决**：针对现有死循环 `run_agent_loop` 导致的“双模态数据流污染”现象，通过重组架构进行彻底改良。
- **改造方案**：将 `CopilotConsumer` 升级为“双向响应”。
  - **状态标志**：在 `__init__` 初始化阶段增加 `self.current_mode = 'idle'` 和 `self.agent_task = None` 状态位。
  - **指令路由 (重写 receive 方法)**：
    - **启动 Copilot**：收到 `{"mode": "copilot", "action": "start"}` 时，通过 `self.agent_task = asyncio.create_task(self.run_agent_loop())` 启动后台巡检死循环。
    - **切入 Ask 模式**：收到 `{"mode": "ask"}` 时，立刻中断 Copilot 循环保护通道 (`if self.agent_task: self.agent_task.cancel()`)，确保干扰彻底掐断，随后独立执行 Function Calling 对话下发逻辑。

#### 5.3 AI 引擎：大模型降维打击与容错跑通
- **模型升级联调**：由于 DashScope 的 OpenAI 兼容接口对 Function Calling 的支持依赖底层模型参数级别，联调阶段必须优先指定 `qwen-max` （或 `qwen-plus`）作为驱动内核，跑通基于 `tools` 和 `tool_choice="auto"` 的双轮 API 握手通讯。
- **降级容错**：在模型链路经过验证完全无误之后再进行降级测试，以此屏蔽因为底层模型版本不支持带来的多重变量干扰。

#### 5.4 数据库支持：只读防篡改机制
- **本地函数 (`tools.py`)**：依赖目前表结构的 `DeviceInfo` 与 `AnomalyAlertLog` 构建 `get_device_recent_data` 作为对外的唯一查询入口。
- **安全隔离**：严禁在此阶段修改任何 `current_group_id` 状态，只允许 `SELECT` 的只读隔离。这一安全措施也更贴合工业级场景下对于生成式 AI 越限操作的防火墙准则诉求。
