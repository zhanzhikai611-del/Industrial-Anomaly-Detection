# 工业生产数据异常预警系统 —— 仿真引擎深度设计与实现 (V3.5.0)

## 1. 仿真引擎概述 (`simulate_real_cnc_data.py`)
系统内置了一个高仿真的工业数据引擎，模拟 25 台 CNC 机床的 7×24 小时运行。它不仅生成传感器原始值，还模拟了设备从“新机”到“磨损”再到“故障”的物理退化全过程。

---

## 2. 核心仿真算法与实现函数

### 2.1 物理特征仿真 (`_gen_production_record`)
这是引擎最核心的函数，负责合成每一条传感器记录。
*   **输入参数**: `device` (设备对象), `timestamp` (时间戳), `group_idx` (当前损耗梯度 0-4)。
*   **损耗梯度联动**: 
    *   根据 `device.current_group_id` 从 `GROUP_BASES` 字典获取基准值。
    *   **主轴电流 (SC)**: `sc_mean = base_sc + off_sc`。随 `group_id` 增加，基准电流从 15A 升至 36A。
    *   **主轴功率 (SP)**: 模拟功率跟随负载波动的过程。
    *   **进给速度 (FV)**: 联动逻辑：`fv_mean = 20.0 - (sc_mean - 15.0) / 10.0`。即磨损越严重，阻力越大，进给速度理论中心越低。
*   **波动合成**: 使用 `np.random.normal` 生成符合高斯分布的噪声，确保曲线具有工业现场的随机抖动。

### 2.2 产量脉冲累加逻辑 (Yield Pulse)
为了精确模拟 OEE 中的“性能稼动率”，系统采用了 **V5 脉冲累加算法**：
1.  **计算份额**: `input_fraction = (cap / 60.0) * effective_mins`。
2.  **效率缩放**: `pulse = input_fraction * perf_ratio`。`perf_ratio` 随设备损耗（Group ID）而下降。
3.  **缓冲区存储**: 将 `pulse` 累加至 `device.yield_buffer`。
4.  **离散化产出**: 当 `yield_buffer >= 1.0` 时，才认为生产出了 1 件成品，并执行 `device.yield_buffer -= produced`。
    *   *意义*: 这种逻辑解决了 3 秒一跳的短采样周期内无法产生“整件”产品的问题，使产量统计在宏观上极其精准。

### 2.3 实时运行循环 (`run_realtime_simulation`)
该函数在后台守护进程中常驻，模拟车间实时生产。
*   **并发处理**: 使用 `ThreadPoolExecutor(max_workers=25)` 为每台设备开启独立线程进行计算，解决大规模写入的延迟。
*   **状态同步**: 每一圈循环（约 3 秒）都会执行 `dev.refresh_from_db(fields=['current_status', 'current_group_id'])`。
    *   *关键功能*: 若用户在前端或 Agent 下发了“维修/停机”指令，仿真引擎能在 3 秒内感知并停止数据生成。
*   **缓存镜像**: 调用 `CacheService.update_device_snapshot`，将最新生成的特征值同步写入 Redis，供前端大屏极速读取。

## 3. 在线推断流程实现

### 3.1 毫秒级推断集成
仿真引擎在调用 `ProductionSensorData.objects.bulk_create` 写入数据库之前，会先完成 AI 推断：
1.  **调用函数**: `ai_service.predict_proba(rec)`。
2.  **特征扩容**: `ai_service` 内部会维护一个 `_DEVICE_BUFFERS` (基于 `collections.deque`)，存储最近 600 秒的历史数据。
3.  **多维特征构造**: 
    *   计算 60 秒均值 (`sc_m1`)、300 秒均值 (`sc_m5`)、600 秒均值 (`sc_m10`)。
    *   计算交互特征：`inter = sc_m5 * sp_m5`。
    *   计算效率特征：`eff5 = sp_m5 / (abs(sc_m5) + 0.01)`。
4.  **模型预测**: 将 13 维特征喂给 `_LR_MODEL.predict_proba()`，并将输出概率 `prob` 直接赋值给 `rec.anomaly_score`。

## 4. 维修联动逻辑 (数据回春)
当 `run_realtime_simulation` 检测到 `dev.current_group_id` 变小（例如从 G5 变为 G1）时：
*   **动作**: 自动调用 `ai_service.reset_device_buffer(curr_id)`。
*   **函数实现**: 
    ```python
    def reset_device_buffer(device_name: str):
        if device_name in _SMOOTHED_PROBS: del _SMOOTHED_PROBS[device_name]
        if device_name in _DEVICE_BUFFERS: _DEVICE_BUFFERS[device_name].clear()
    ```
*   **效果**: 强制清空该设备的 EMA 平滑缓冲区，使大屏上的风险分数瞬间从 90% 掉回 5% 以内，直观体现维修效果。

## 5. 高级仿真特性 (V3.5.0 专项)

### 5.1 基于马尔可夫链的状态转移模拟
系统通过加工阶段权重（`STAGE_PROBS`）模拟了 CNC 的真实加工逻辑：
*   **切削触发机制**：只有处于 `Layer 1/2/3 Up/Down` 阶段时，AI 模型才会更新其推断状态，模拟了真实工业场景中非切削期的信号屏蔽逻辑。
*   **异常概率分布**：通过 `ANOMALY_PROB` 参数，在磨损后期（G4-G5）高概率注入突发性物理尖峰（Spikes），用于测试系统的硬报警（Hard Alert）触发能力。

### 5.2 性能 P 值与良率 Q 值的解耦模拟
*   **性能下降 (Performance)**：随 `group_idx` 增加，`perf_ratio` 线性下降，模拟刀具变钝导致的加工效率降低。
*   **质量损失 (Quality)**：引入 `defect_buffer` 缓冲区。只有当设备处于高磨损状态时，次品产生的脉冲才会积累到整数件，实现了良率随设备健康状况恶化的真实反馈。

### 5.3 线程池并发下的原子性保障
在 25 台设备并发执行时，系统通过 `refresh_from_db(fields=...)` 仅拉取状态字段，并配合内存中的 `yield_buffer` 闭环计算，确保了在多线程竞争环境下生产数据的原子累加。
